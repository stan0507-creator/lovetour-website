# CMS Admin Screens

Phase 8 目標：規劃樂圖漫遊會館 CMS 後台畫面與操作流程。  
本文件只規劃後台資訊架構，不建立完整後台、不公開部署、不改變目前網站內容發布狀態。

## 後台設計原則

- 業主不需要修改程式碼。
- 後台文字以繁體中文為主。
- 每個畫面都要清楚標示內容狀態：草稿、已確認、已發布、下架。
- 未填或未確認的欄位只出現在後台，不出現在旅客網站。
- 圖片必須可管理 alt、用途、排序與是否正式使用。
- 房價、即時房況、付款與訂單不在網站 CMS 管理，改由奧丁丁處理。
- 「發布」應有確認步驟，避免誤按。

## 1. 儀表板

用途：讓業主快速知道目前網站內容狀態。

可查看：

- 已發布內容數量。
- 草稿內容數量。
- 已確認但未發布內容數量。
- 待補欄位提醒。
- 近期發布紀錄。
- 圖片尚未補 alt 的提醒。
- 房型是否缺少封面圖或奧丁丁連結。

可修改：

- 不直接修改內容，只提供捷徑到對應畫面。

可發布：

- 不建議在儀表板直接發布，避免誤操作。

## 2. 品牌與聯絡資料

對應 collection：`Site Profile`

可查看：

- 民宿中文名稱。
- 英文名稱。
- Slogan。
- 品牌簡介。
- 經營理念。
- 地址。
- 電話。
- Email。
- LINE ID 與 LINE 官方網址。
- Facebook / Instagram。
- 官方網站網址。
- Google Maps 連結。
- 回覆時間。
- 入住與退房時間。

可修改：

- 品牌文字。
- 聯絡方式。
- 社群與地圖連結。
- 全站共用 CTA 相關設定。

可發布：

- Owner 可發布。
- Editor 可儲存草稿或送確認。

注意：

- LINE 官方完整網址、Google Maps 連結若空白，前台不可自行產生。
- 地址需人工確認，避免「西衛里」等地名誤植。

## 3. 館別管理

對應 collection：`Property`

可查看：

- Love 館資料。
- Tour 館資料。
- 館別介紹。
- 館別特色。
- 地址是否共用。
- 館別照片。
- 所屬房型。

可修改：

- 館別名稱。
- 館別摘要與詳細介紹。
- 館別特色。
- 館別照片。
- 顯示順序。

可發布：

- 館別基本資料可單獨發布。
- 若館別照片未確認，只能保留草稿或已確認，不可發布照片。

## 4. 房型管理

對應 collection：`Room`

可查看：

- 12 間房型列表。
- 所屬館別。
- 房號。
- 正式房名。
- 建議入住人數。
- 最多入住人數。
- 床型與床數。
- 是否可加床。
- 房內設備。
- 衛浴設備。
- 房型特色。
- 注意事項。
- 封面圖。
- 相簿圖片。
- 奧丁丁訂房連結。
- LINE 詢問連結。
- 顯示順序。
- 發布狀態。

可修改：

- 房型文字。
- 設備與特色排序。
- 封面圖與相簿排序。
- 奧丁丁連結。
- LINE 詢問連結。
- 是否顯示於首頁或列表。

可發布：

- 只有資料完整且通過檢查的房型可發布。
- 若缺正式照片、奧丁丁連結或最多入住人數，可依業主決定是否仍發布，但前台不可顯示未確認文字。

建議列表欄位：

- 房號。
- 房名。
- 館別。
- 狀態。
- 是否有封面圖。
- 是否有奧丁丁連結。
- 最後修改時間。

## 5. 包棟管理

對應 collection：`Villa Rental`

可查看：

- 包棟館別。
- 適合人數。
- 不加床標準容量。
- 房間配置。
- 床型配置。
- 公共空間。
- KTV。
- 麻將。
- 烤肉。
- 廚房設備。
- 電梯。
- 接送說明。
- 入住與退房規則。
- 夜間音量提醒。
- 包棟 CTA。
- 奧丁丁包棟網址。

可修改：

- 包棟介紹。
- 包棟設備。
- 服務提醒。
- FAQ 關聯。
- 包棟照片。
- LINE 預設詢問文字。
- 包棟訂房或詢問連結。

可發布：

- Owner 可發布。
- 未確認押金、清潔費、訪客、設備賠償與垃圾規則時，前台不可顯示這些欄位。

## 6. 照片與相簿

對應 collection：`Media Asset`

可查看：

- 全部圖片。
- 圖片用途。
- 所屬館別。
- 所屬房型。
- 是否為封面。
- 是否已確認。
- alt 文字。
- 圖片尺寸。
- 上傳時間。

可修改：

- 圖片名稱。
- alt 文字。
- caption。
- tag。
- 所屬房型或館別。
- 排序。
- 是否可用於正式網站。

可發布：

- 圖片本身不建議單獨發布到前台，應隨房型、館別或頁面內容一起發布。

注意：

- 原始照片不可覆蓋或刪除。
- 未經業主確認的照片不得移入正式素材狀態。
- 圖片需支援封面與相簿排序。

## 7. FAQ

對應 collection：`FAQ`

可查看：

- 問題。
- 答案。
- 分類。
- 顯示順序。
- 狀態。

可修改：

- 問題文字。
- 答案文字。
- 分類。
- 排序。

可發布：

- Owner 可發布。

對應 collection：`Policy`

可查看：

- 入住與退房。
- 提前入住。
- 延後退房。
- 接送。
- 停車。
- 加床。
- 兒童。
- 寵物。
- 吸菸。
- 訪客。
- 付款。
- 訂金。
- 取消與改期。
- 天候與交通異常。
- KTV、麻將、烤肉。
- 垃圾與遺失物。

可修改：

- 政策類型。
- 標題。
- 內容。
- 生效日期。
- 狀態。

可發布：

- Owner 可發布。
- 對旅客權益有影響的政策發布前需再次確認。

提醒：

- 未確認的政策不可顯示「待確認」到前台。
- 前台可選擇不顯示該項目，或顯示保守通用說法。

可查看：

- slug。
- 分類。
- 摘要。
- 封面圖。
- 發布日期。

- SEO title。
- SEO description。

- 圖片。
- 分類。

## 10. SEO

對應 collection：`SEO Settings`

可查看：

- 首頁 SEO。
- 關於頁 SEO。
- 房型列表 SEO。
- 單房型 SEO。
- 包棟頁 SEO。
- FAQ SEO。
- 交通位置 SEO。
- 聯絡頁 SEO。
- Open Graph 圖片。
- favicon。

可修改：

- title。
- description。
- canonical path。
- OG image。
- noindex。

可發布：

- SEO 可跟頁面內容一起發布。
- 若 SEO 缺漏，後台應提示但不一定阻擋發布。

## 11. 連結設定

對應 collection：`Link Settings` 或 Site Profile nested fields

可查看：

- LINE 官方網址。
- Google Maps 網址。
- Facebook。
- Instagram。
- 官方網站網址。
- 奧丁丁全站入口。
- 各房型奧丁丁連結。
- 包棟詢問連結。
- 電話連結。

可修改：

- 所有外部連結。
- CTA 啟用或停用。

可發布：

- 外部連結需通過格式檢查。
- 未填 LINE 官方完整網址時，不啟用 LINE CTA。
- 未填奧丁丁連結時，不啟用「立即訂房」CTA。

## 12. 草稿預覽

用途：讓業主在發布前看到前台畫面。

可查看：

- 首頁草稿。
- 房型頁草稿。
- 包棟頁草稿。
- FAQ / 政策草稿。
- 最新消息草稿。

可修改：

- 不直接修改，提供回到原內容編輯頁的連結。

可發布：

- 預覽畫面不直接發布。
- 預覽畫面需顯示內部提示：請勿公開使用。

規則：

- 草稿預覽可讀 draft 與 verified。
- 正式網站只讀 published。

## 13. 發布紀錄

用途：追蹤誰在什麼時間發布或下架內容。

可查看：

- 發布時間。
- 發布者。
- 內容類型。
- 內容標題。
- 從哪個版本發布。
- 是否有回復紀錄。

可修改：

- 不建議修改發布紀錄。

可發布：

- 不適用。

可還原：

- Owner 可選擇回復上一版。
- Developer 可協助技術復原。

## 發布前檢查清單

任何內容發布前，後台應提示：

- 是否有「待確認」或內部備註文字。
- 必填欄位是否完整。
- 圖片是否有 alt。
- 外部連結是否有效。
- 房型是否有 slug。
- SEO title 與 description 是否存在。
- 內容狀態是否為 verified。
- 是否已由 Owner 確認。

## 權限建議

| 功能 | Owner | Editor | Developer |
| --- | --- | --- | --- |
| 修改內容 | 是 | 是 | 技術協助 |
| 上傳圖片 | 是 | 是 | 技術協助 |
| 草稿預覽 | 是 | 是 | 是 |
| 標記 verified | 是 | 可送審 | 否 |
| 發布 published | 是 | 否 | 除非授權 |
| 下架 archived | 是 | 否 | 除非授權 |
| 還原版本 | 是 | 否 | 技術協助 |
| 修改 schema | 否 | 否 | 是 |

## 最小 PoC 後台範圍

Phase 8 若進行概念驗證，只能包含：

- 1 個 Site Profile。
- 1 個 Property。
- 1 個 Room。
- 1 個 FAQ。

PoC 不得：

- 覆蓋目前 TypeScript 內容資料。
- 將任何內容設為 published。
- 公開部署。
- 串接奧丁丁 API。
- 建立 AI、付款、訂單或會員功能。
