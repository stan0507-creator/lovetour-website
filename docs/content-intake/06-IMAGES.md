# 06 照片交付清單

這份文件用來確認正式網站需要哪些照片。  
請依實際交付狀況填寫「是否已提供」與檔名。不確定的欄位可以先填「待確認」。

## 盤點狀態

```text
階段性收束：照片整理規則已確認，正式素材待後續交付與盤點。

原始照片整理方式已確認。
照片實際內容、畫質、房型對應及是否需要重拍，仍待後續盤點。
原始照片不可覆蓋、刪除或直接轉檔。
未經業主確認的照片，不得移入正式網站圖片目錄。
未經確認的照片不得標記為 published。
現有網站示意圖片暫時保留，直到正式照片完成替換。
未來 CMS 後台需支援房型封面圖、相簿圖片、館別照片、包棟設施照片與排序管理。
```

## 目前已知照片來源

```text
已確認可先整理：
- 樂圖漫遊現有官網。
- 手機相簿。
- 電腦或外接儲存裝置。
- Facebook 或其他社群平台。

待確認是否另有照片：
- Google 雲端。
- 相機記憶卡。
```


```text
12 間房皆需逐間確認照片數量、畫質與目前房況是否一致。

Love 館與 Tour 館外觀照片目前先標記為待盤點，需確認是否具備：
- 白天外觀。
- 夜間外觀。
- 建築入口。
- 招牌。
- 兩館辨識照片。

Tour 館包棟設施照片分開標記：
- KTV：待盤點。
- 麻將空間：待盤點。
- 烤肉空間：待盤點。
- 公共空間：待盤點。
```

## 交付與命名規則

```text
現有官網照片：
- 可以作為第一批盤點來源及比對參考。
- 不要直接視為最高畫質正式原檔。
- 若能找到手機、電腦或攝影時留下的原始照片，應優先使用原始檔。
- 舊官網下載的照片可能已被壓縮。

手機相簿照片：
- 之後由業主先挑選並匯出，再放進照片整理資料夾。
- 目前不需要處理整個手機相簿。

照片檔名：
- 第一階段先保留原始檔名，不要立即批次重新命名，以免無法追溯照片來源。
- 完成房型與用途確認後，再統一複製並命名為網站格式。
- 原始照片需保留不變，不要覆蓋或刪除。

未來網站格式範例：
- love-1201-cover.webp
- love-1201-01.webp
- tour-2201-cover.webp
- tour-ktv-01.webp
```

## 重新拍攝狀態

```text
目前暫不全面重新拍攝，先盤點既有照片的內容、畫質、比例及是否符合目前實際房況。

盤點後再將照片分為：
- 可直接使用。
- 需要裁切或調整。
- 畫質不足。
- 與目前房況不符。
- 建議重新拍攝。
```

## 本階段禁止事項

```text
本階段不要：
- 從舊官網大量下載照片。
- 壓縮或轉檔原始照片。
- 刪除原始照片。
- 修改目前網站示意圖片。
- 將照片標記為 published。
- 自行判斷照片對應哪一間房。
```
