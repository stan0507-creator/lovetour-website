# 技術選型與架構

## 專案目標

樂圖漫遊會館官網的主要目標是讓旅客快速理解住宿特色、房型、位置、入住須知與詢問方式。網站需要容易維護、SEO 友善、載入快速，並保留日後擴充訂房詢問、活動專案、文章內容與多語系的空間。

## 技術選型

### 前端框架：Astro + TypeScript

Astro 適合內容型網站與品牌官網，預設輸出靜態頁面，速度快、SEO 友善，也能在需要互動的區塊使用小型 client island。TypeScript 用來保護館別、房型、FAQ、交通資訊、CTA 與內容發布狀態等資料結構。

### 樣式策略：Design tokens + 元件級 CSS

第一階段先定義樣式組織方式，不導入大型 UI framework。正式實作時會建立色彩、字級、間距、陰影、斷點等 tokens，再由元件使用。這能保留現在的海島民宿風格，也避免後期 CSS 混亂。

### 內容管理：本地內容檔先行，CMS 延後

初期內容建議放在 `src/content/`，使用 JSON、YAML 或 Markdown/MDX。這讓房型、FAQ、專案活動可以先穩定建模。若日後需要民宿業主自行登入更新，再評估 Headless CMS。

### 部署方向：靜態網站優先

優先部署為靜態網站，可放在 Cloudflare Pages、Vercel、Netlify 或主機商靜態空間。訂房詢問先導向 Line、電話或表單通知，暫不建立付款與即時庫存後台。

## 模組邊界

- `site-content`：品牌文字、首頁區塊、FAQ、入住須知。
- `properties`：Love 館、Tour 館與未來館別資料。
- `rooms`：房型、容量、設施、照片、館別關係與 CTA 資料。
- `offers`：花火節、包棟、淡旺季專案。
- `booking-inquiry`：詢問表單、Line 訊息、電話入口。
- `location`：地圖、交通、附近景點與抵達方式。
- `media`：圖片資產、替代文字、圖片使用規範。
- `seo`：meta、結構化資料、Open Graph、sitemap。

## 目前仍不做的事

- 不建立 CMS 或後台。
- 不建立 API route。
- 不建立 AI 功能。
- 不串接奧丁丁或正式訂房流程。
- 不串接 Line、Google Maps、Analytics 或後端表單。
- 不建立付款、房況庫存、會員或後台系統。
- 不把 Phase 0 視覺原型當作正式內容來源。

## 架構決策

目前採用「內容資料先建模，頁面再實作」的順序。  
這樣後面每一個頁面都能從一致資料來源產生，避免房型資訊在多個頁面重複手改。
